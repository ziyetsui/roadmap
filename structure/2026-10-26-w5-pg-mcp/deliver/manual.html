        步骤 1 判断：什么时候该用 MCP，什么时候用 CLI 或 Skill

        目标：用你自己 Claude Code 里看到的上下文数字，写出一张"这个能力用 MCP、CLI 还是 Skill"的决定表。

        讲者做法与数字

        • MCP 是 AI 应用的"USB 接口"：用 JSON-RPC 2.0（一种用 JSON 写"调用哪个方法、带什么参数"的通信格式）把工具能力标准化，解决 N 个工具要适配 M 个模型的问题。[00:01:55] [O1]

        • "非必要不要使用 MCP"[00:21:50]；CLI 的好处是能力可以逐步暴露，模型先看到一句简短描述，需要时自己去查子命令[00:22:30]；MCP 的优势是有状态[00:23:47]；几个选项里"MCP 的优先级应该放在最后"[00:25:44]。[O1]

        步骤 2 建测试库和只读账号

        讲者的原则是"代码写好了，最好也把这个代码所需要的测试数据准备好"。课程的 pg-mcp/fixtures/ 目录里有三份建库 SQL 和一个 Makefile，一条命令就能建好三个库。课程讲者是边写代码边建库，这里提前做，后面每一步都有真数据可查。

        目标：本机有 blog_small、ecommerce_medium、saas_crm_large 三个库，make test-all 的数字和课程的 TEST_RESULTS.md 一致，另有一个只能读不能写的账号。

        1. 确认服务：运行 pg_isready。本机 2026-10-26 返回 accepting connections，但只有 ziye 角色、没有 postgres 角色，三个库都还不存在。fixtures 的 Makefile 默认用 postgres 用户登录。[O10、O12]
