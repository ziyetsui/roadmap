# W5 原提示词下方模板补充

助手抽象模板；替换〔〕后使用。

## 1

```text
主要需求是在〔语言／平台〕下创建〔服务类型〕：用户给〔自然语言需求〕，服务返回〔生成产物〕或〔执行结果〕。启动时读取〔可访问资源〕并缓存〔结构与元数据〕；结合结构与输入，调用〔模型与配置〕生成〔产物〕。校验〔允许的操作与安全边界〕后试运行，结合输入、产物与部分结果确认是否有意义，最后按用户选择返回对应内容。根据这些需求写详细 PRD 到〔PRD 路径〕，先不要设计，等我 review 后再讨论设计。
```

## 2

```text
提交〔当前已检查的改动〕；将接口范围收敛到〔保留的核心接口〕，暂不实现〔排除的接口〕。调用〔独立评审模型／工具〕评审〔PRD 路径〕，逐条判断意见是否合理，再更新需求文档并记录采纳与不采纳的理由。
```

## 3

```text
根据〔PRD 路径〕，使用〔框架、数据访问、解析校验、结构化建模与模型调用库〕编写〔项目名〕的设计文档，说明模块、数据结构、接口及关键流程，保存到〔设计文档路径〕。
```

## 4

```text
使用〔独立评审 agent〕调用〔评审工具／模型〕评审〔设计文档路径〕。仔细阅读结果，判断是否符合〔项目范围与约束〕，再据此更新设计文档，保留评审记录到〔评审路径〕。
```

## 5

```text
根据〔设计文档路径〕，深入思考并编写〔项目名〕的实施计划，保存到〔实施计划路径〕。拆分阶段与依赖，并写清各阶段产物和验收条件。再调用〔评审工具／模型〕评审计划，将结果保存到〔计划评审路径〕。
```

## 6

```text
根据〔实施计划路径〕和〔设计文档路径〕，使用〔执行 agent〕完整实现〔项目名〕的〔起始阶段〕至〔结束阶段〕。代码放在〔代码目录〕，按阶段要求核对实现和测试，记录未完成项。
```

## 7

```text
根据〔实施计划路径〕和〔设计文档路径〕，为〔项目名〕编写可以实际执行的测试计划，保存到〔测试计划路径〕。覆盖〔关键流程、错误路径与边界条件〕，说明环境、数据、命令与预期结果。再调用〔独立评审工具／模型〕评审，将结果保存到〔测试计划评审路径〕。
```

## 8

```text
根据〔PRD 路径〕，在〔fixtures 目录〕构建〔规模层级列表〕的有意义测试数据库，覆盖〔表、视图、类型、索引与业务关系〕及〔各层数据量要求〕。生成各库 SQL 和用于重建的〔构建脚本〕，写明库名与验证方法。
```

## 9

```text
提交〔本轮测试数据文件〕，使用〔本地连接配置〕建立〔目标测试数据库列表〕并测试可用性。执行〔建库命令〕与〔验证命令〕，核对〔结构、类型、索引和数据量〕，记录实际结果及失败原因到〔验证记录路径〕。
```

## 10

```text
根据〔实施计划路径〕和〔设计文档路径〕，使用〔执行 agent〕完整实现〔项目名〕的〔剩余起始阶段〕至〔结束阶段〕。代码放在〔代码目录〕，运行〔验收测试命令〕并修复失败，记录尚未完成的检查。
```

## 11

```text
提交〔本轮实现改动〕，使用〔独立评审 agent〕调用〔代码评审工具／模型〕审查〔代码目录〕，逐项核对〔设计文档路径〕和〔实施计划路径〕。将问题、证据、影响及建议写到〔代码评审路径〕。
```

## 12

```text
将〔代码目录〕的〔MCP 服务名〕接入〔客户端项目〕。启动另一个〔客户端 headless 命令〕会话，从〔测试问题集路径〕选择〔问题编号列表〕执行，检查是否实际调用目标 MCP，并将输入、调用、结果与预期对照写入〔验证记录路径〕。
```

## 13

```text
直接用本地命令 `uvx --refresh --from 〔项目绝对路径〕 〔入口命令名〕` 运行〔MCP 服务名〕。按〔环境配置位置〕补齐连接参数，再检查客户端是否能够列出并调用预期工具。
```

## 14

```text
在〔项目内 Skill 目录〕创建〔Skill 名〕：
1. 使用〔命令行客户端与连接配置〕探索〔数据库列表〕的〔表、视图、类型、索引等结构〕，每库生成一份 reference 文件。
2. 根据用户的自然语言需求选择 reference 并生成 SQL，只允许〔查询操作集合〕，禁止〔写操作、危险函数、注入和敏感信息泄露〕。
3. 用〔命令行客户端〕执行 SQL；失败则分析原因、重新生成并重试。
4. 结合用户输入、SQL 与部分结果，按〔评分量表〕评估意义；低于〔置信阈值〕则重新生成并回到执行验证。
5. 按用户要求返回 SQL 或查询结果，默认返回〔默认返回内容〕。
```

## 15

```text
为〔项目名〕生成〔项目规则文件路径〕，符合〔语言及工具链〕的最佳实践，遵守〔设计原则〕，明确代码质量、测试质量及检查命令。
```

## 16

```text
避免超出〔当前阶段范围〕的过度设计，暂不考虑〔暂缓事项〕。将设计恢复到〔保留的设计范围〕，把〔独立模型／工具〕的评审意见保存到〔设计评审路径〕，列清本轮采纳与暂缓内容。
```

## 17

```text
根据〔fixtures 目录〕，假设用户通过自然语言提问、〔查询服务名〕生成 SQL。在〔测试问题集路径〕生成从简单到复杂的问题，覆盖〔数据库列表与业务关系〕，并按〔难度层级〕组织。
```

## 18

```text
〔Skill 名〕存在〔具体故障现象〕，影响〔操作／产物〕。请检查〔Skill 目录及相关调用链〕，定位原因、修复并验证〔复现步骤与预期行为〕。
```

## 19

```text
附件是〔项目一句话描述〕的〔PRD 路径／需求文档〕。如果用〔语言与运行环境〕实现，应为〔功能类别列表〕分别选择哪些库？逐项给出首选、备选及选择理由，引用〔官方文档与源码来源〕，说明与需求的对应关系，输出到〔调研记录位置〕。
```

## 20

```text
深度研究〔库名〕，了解它的设计理念、支持的〔语法／功能范围〕及限制。结合〔项目使用场景〕判断能否满足〔关键需求〕，列出依据与待验证问题，将结论保存到〔调研文档位置〕。
```

## 21

```text
使用〔MCP 服务名〕的〔工具名〕，传入〔测试参数〕，告诉我工具返回的原始值，并与〔预期返回值〕对照，确认实际调用了该工具。
```

## 22

```text
阅读〔代码评审路径〕，列出〔本轮要补的缺失功能与优先级〕，对照〔设计文档与实施计划〕逐项实现；每项补对应验证并运行〔测试、静态检查与构建命令〕。记录仍未完成项，最后用〔独立评审工具／模型〕复核实现是否满足评审要求。
```
